# Codex 五小时窗口保活修复方案

## 目标与证据

默认账号目录可显式配置为 `~/.codex`。保留每 600 秒一次的调度，修复未初始化窗口的重置时间随查询向后移动、keeper 却永远跳过的问题。

故障日志中连续多个定时查询都显示剩余约 299 分钟，没有 ping。原代码只判断 `resetsAt > now`，因此把随查询时间移动的重置时间误判为已开启窗口。这是滑动窗口的强证据；“补发之后服务器重置时间固定”仍须真实闭环验证。

## 判定合同

1. 按 `windowDurationMins=300` 选择五小时窗口，不把 primary 的位置当成时长保证。缺少该窗口、字段非法、RPC 失败均不得自动发请求。七天窗口、五小时窗口、后端 `rateLimitReachedType` 或有效期内的个人额度明确耗尽时跳过。
2. 每次 tick 保存账号标识、额度桶、套餐、查询时间、窗口时长、使用率和真实重置时间。状态绑定实际 CODEX_HOME 和文件凭据的账号身份；切换账号、旧格式状态不得沿用历史判断。状态中损坏的观测字段不得绕过可信的成功请求保护。
3. 使用率大于 0 且重置时间在未来：窗口已有使用，跳过。
4. 使用率为 0 时比较两次定时采样：间隔 300–1200 秒，允许 60 秒时间容差。重置时间基本固定并有可见倒计时，按已有窗口处理；两次均接近“查询时间 + 18000 秒”，重置时间增量近似查询间隔，才识别滑动并补发一次。过去的明确重置时间可触发补发。
5. 首次运行、窗口切换、时间回退、间隔过长或数据矛盾时先观察。短时间重复查询可能读到缓存，不作为确认手段。旧窗口已过期时不得用它证明新窗口固定。时间回退只丢弃比较样本，重建并持久化请求保护期限，防止清空成功记录导致重复请求或每次检查再次延长退避。
6. 通常每次 tick 只查询一次；ping 完成后立即再查一次保存候选值，后续正常 tick 确认。最差可能在窗口过期后接近 20 分钟才补发；机器睡眠或网络失败时不保证此上限。

## 状态与请求约束

- 将检查时间、请求尝试时间、成功完成时间、真实重置时间和 `retry_after` 分开。旧版 last_ping 在 skip 时也更新，迁移时不能当成成功记录。
- 请求完成不等于窗口已经确认。成功后显示待确认；有使用量或后续固定倒计时才确认窗口，以实际重置时间为准。
- 显式请求前已确认的活跃窗口也是有效证据：后置查询失败或返回无效数据时保留它，不能因此错过更早的真实到期。额度桶或套餐改变时，已有确认时间和未确认请求保护不得套用到新窗口。
- 成功但无法确认的自动请求最多五小时一次，仍持续查询；不能把这个本地保护期限显示为服务器重置时间。确认实际窗口后解除该保护，服从真实到期时间。
- RPC 或请求失败时落实 `BACKOFF_SECS=1800`：到期前 tick 不重试。执行请求前先持久化尝试时间和保护期限，降低崩溃造成重复请求的风险。
- status、dry-run 和 tick 共用判定逻辑。status 与 dry-run 不改状态、不发请求；缓存状态必须标为 stale/UNKNOWN。
- 保留显式 ping/--force：可绕过普通观察与间隔保护，但仍要求有效额度数据，尊重已知额度耗尽，且仍受账号锁保护。
- 明确配置 `CODEX_HOME_default` 可使手工命令与 launchd 都监控 `~/.codex`。日期格式化按 date 的实际能力选择，支持 macOS 下 GNU date 优先的 PATH。

## 实施顺序

1. 写回归测试，先证明原代码不能正确处理滑动的 0%、固定的 0% 和失败退避。
2. 实现共用判定及版本化状态；落实请求防重、真实退避和成功后确认。
3. 修正 status、日期兼容及账号目录选择；更新 README、配置示例。
4. 在 Bash 3.2 下运行全部测试、语法和差异检查，检查并发与重启行为。
5. 部署时备份现有二进制和配置，原子替换已安装脚本，明确默认账号目录，验证真实只读额度查询与定时任务。

## 验收

自动测试覆盖：固定/滑动 0%、有使用量、窗口切换、缓存、时间变化、失效历史、重启、旧状态迁移、账号切换、失败退避、成功但不能确认、缺失/非法字段、周额度与个人额度耗尽、后端耗尽信号、损坏状态保护、dry-run/status 无副作用、并发锁及 GNU/BSD date。

真实验收路径：自然出现滑动 → keeper 只补发一次 → 后续重置时间固定并倒计时 → 下一次 tick 不再发送。当前活跃窗口上的一次强制 ping 不代替这项验收。不得通过改系统时钟或篡改真实额度状态伪造验证。

## 已完成的验证

- 原始测试和新增生命周期测试覆盖滑动漏发、失败退避、检查冒充 ping、时钟回退与后置查询失败等回归场景。
- 在 macOS Bash 3.2 下验证 GNU 工具优先和系统工具优先的 PATH；运行语法检查与 `git diff --check`。
- 实机上完成一次显式 ping，随后启动真实定时任务执行 tick：活跃窗口被跳过，最后成功 ping 时间没有变化。
- **真实自然开窗验收仍待观察**：验证时窗口已活跃，无法在本次短时验证中证明“自然滑动 → 自动补发 → 固定倒计时”。后续可查看 `keeper.log` 中 `zero-use reset slides with observation time`、`ping ... completed` 和随后的 `skip ... window active`。

## 回滚

恢复备份中的 `codex-window-keeper` 到 `~/.local/bin/codex-window-keeper`（权限 755）、`config` 到原配置路径；需要旧版状态时同时恢复 `state.json`。操作应在该账号没有正在运行的 keeper 时进行。此修复无需修改定时器定义。
